# 终极 v2 开发与测试计划

日期：2026年09月07日  
目标版本：0.3.0  
状态：实现、测试与 0.3.0 发布已完成，强度目标尚未通过。本文保留预定方案，实际结果见[终极 v2 验收记录](终极v2验收记录.md)；正式留出因未达到进入门槛而未启动。

## 目标与范围

在桌面浏览器可接受的思考时间内提高终极策略的实际表现。沿用普通 Ludo 棋规、独立公平骰子、本地计算、单文件 HTML、Worker 取消与故障恢复。当前高级与旧终极冻结为对照，不通过削弱其它难度制造差距。手机适配仍暂缓。

旧版快照位于 `tests/fixtures/ai-v1/`，其源文件摘要与历史部署的 AI、引擎一致。实验和产品使用同一棋规引擎，不允许策略读取裁判种子、未来骰点或修改真实状态。

## 实施顺序

1. **预算对照**：比较旧终极 60,000 节点与增加节点额度的原算法，均保留 600ms 时间保护。检查更多额度是否带来完成深度、动作和胜率变化。
2. **局面评分**：增加无对手干扰情况下的单子完成成本、有限归家残局的单方完成效率、可用骰点和当前行动顺序下的风险特征。单子成本及单方残局表不能称为整局精确剩余回合或真实胜率。
3. **模拟续玩**：对所有不同根走法进行有策略的模拟续玩，配对模拟种子，完整轮次才更新选择。模拟随机数与真实骰子分离，真实终局、截断和静态先验分别记录，混合结果只能称估计价值。
4. **候选选择**：先分别比较预算、评分与续玩，胜出后才决定产品采用哪一项或组合。保留失败候选及结果，不把复杂程度等同于强度。
5. **产品与发布**：接入既有 Worker、难度按钮和版本记录，完成正确性、浏览器及对战验证后再发布。若强度证据不足，必须如实记录，不宣称已证明四档强度有序。

开发中增加一项窄范围能力：仅当双方未完成棋子全部进入专属归家通道时，解算有限状态的终局获胜概率。处理无动作与连续 6 的循环，仅在所有根走法完整求解时采用结果。默认在单步 600ms 总预算内先分配最多 120ms，未完成则把剩余时间交给常规搜索。它不能把一般局面的估分转换成真实胜率，也不自动证明整局更强。

## 开发和验证实验

开发批次每个预定候选先运行 8 个独立种子块，每块 4 局，共 32 局。每块轮换双方阵营与先后手，使用相同的裁判骰流；不同走法可以改变骰流消耗长度。候选参数、依赖源码摘要、种子和模式写入 manifest，按完整块恢复。

开发集用于诊断与调参。验证集另用独立种子，候选对高级和旧终极分别运行 16 块，共 64 局，选择最终配置。不同算法以同设备、同实际时间和内存约束比较，不能把相同节点数当作相同计算成本。节点模式用于确定性开发，发布强度需要核对实际时间保护是否改变动作或增加实际时间模式验证。

在启动独立验证前确定进入留出的条件：两组验证都取得全部真实终局、没有错误或截断，且观察胜率均至少 55%，再进入下面的正式留出。开发与验证用于筛选，不用于正式显著性结论；没有达到条件时保留失败证据，不为取得通过结果而反复试验留出集。

## 终极 v2 独立留出方案

本轮 v2 验证单独比较两组：最终候选对冻结的高级、最终候选对冻结的旧终极。若候选进入正式留出，预定每组 128 个独立块、512 局，两组共 1,024 局，结果只在计划终点查看一次。它不替代 `AI评测协议.md` 中四档相邻三组的完整验收。

每组块级单侧 Hoeffding 下界使用 `alpha = 0.025`，两组错误率合计上界 5%，以独立有界块模型为前提：

```text
radius = sqrt(log(1 / 0.025) / (2 * blockCount))
lowerBound = max(0, blockMean - radius)
```

强度通过需全部计划局取得真实终局、无错误或截断、观察胜率至少 55%，且下界严格高于 50%。128 块的保守半径约为 12 个百分点，55% 胜率本身不能保证通过。未通过保留结果，不临时改统计方法、扩样到通过或更换留出种子重试；后续改进另作研发记录。

## 正确性与浏览器测试

- 独立核对完成成本及有限残局表。普通评分验证终局 ±1、非终局有界和阵营交换反号；精确残局概率验证终局 0/1、区间 [0,1] 以及交换视角后互补。两者都检查合法动作和输入不变。
- 概率搜索保留完整层；续玩保留完整轮；零预算、时间截止、节点截止、立即获胜和唯一有效动作均返回合法结果。
- 初级、中级、高级与冻结实现做行为回归，不偷改原难度。
- 桌面 Chrome 本地文件与正式 HTTPS 加载后断网对局，统计 Worker 请求耗时、停止原因、界面错误和网络请求。
- 600ms 是策略软预算，沿用 1,500ms Worker 硬保护；终极暖启动请求 P95 目标不超过 850ms，记录测试设备和覆盖范围。
- 思考中重新开局、版本页暂停/恢复及旧 Worker 结果隔离必须通过。
