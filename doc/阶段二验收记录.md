# 高级与终极 AI 验收记录

日期：2026年09月07日  
版本：0.2，阶段二搜索与离线 Worker。  
结论：两档功能、正确性和本机浏览器体验通过。四档相邻强度的正式留出验收尚未完成，不宣称最优或终极必胜。

## 实现

| 等级 | 行为 | 节点上限 | 搜索软预算 |
| --- | --- | ---: | ---: |
| 初级 | 不同合法后继间均匀随机，立即获胜优先 | 无搜索 | 无搜索 |
| 中级 | 完整比较位置、机动性及捕获威胁的静态价值 | 无搜索 | 无搜索 |
| 高级 | 迭代加深的概率对抗搜索 | 12,000 | 150 ms |
| 终极 | 更大计算额度的同一搜索基准 | 60,000 | 600 ms |

根骰点已经确定，根动作之后的一个深度单位为一次未来掷骰及其走子或强制跳过。机会节点枚举六个骰点，各占 1/6；按真实活动方最大化或最小化。连掷 6、第三个 6、无子可走、捕获和精确到家均使用同一棋规内核。

每次请求使用独立缓存，上限 20,000 项；只有完整计算的子树进入缓存。整层所有根动作完成后才更新建议，超限保留上一完整层，尚未完成第一层时保留中级备用。唯一有效后继与立即获胜直接执行。冻结配置见 `LudoAI.LEVEL_CONFIGS`，诊断同时记录完整深度、尝试深度、节点、缓存和停止原因。

主线程和 Blob Worker 从同一份引擎与 AI 源码构建。Worker 无权写真实棋局，也不接收真实骰源或其种子。请求绑定线程实例、棋局、请求编号、状态版本、棋规、棋盘与策略版本。重开和隐藏页面取消搜索；旧返回和旧故障回调不能干扰新请求。前台硬截止为 1500ms，故障时重新核对合法性并使用预先计算的中级动作，界面显示兼容模式。

## 正确性

`npm test` 共 99 项通过，详细输出为 `output/ai-unit-tests.txt`。

- 原棋规与基础 AI 检查保留。
- 快速评估在 250 个布局、双方视角上，与原先基于棋规引擎投影的独立实现数值和特征一致。
- 搜索与独立朴素递归对照，覆盖 max/min 方向、第一次和第二次 6、第三次 6、超点、归家通道和捕获。
- 验证完整层提交、零额度备用、有界缓存、固定额度复现、输入不变、真实随机流隔离与阵营对称。
- Worker 测试覆盖合法返回、身份不符、取消、非法动作、异常、超时、旧故障回调和暖启动复用。
- 评测工具测试覆盖冻结配置、配对、记录校验、分批恢复、截断和统计边界。

## 浏览器与性能

环境：Windows、Intel Core i9-14900HX，桌面 Chrome 152，1440 × 1000。以下是本机样本，不代表所有设备或运营商。

直接打开 `index.html` 后断网完成高级、终极各一整局，分别为 170、175 次掷骰；均取得真实终局。共采集 118 次搜索返回，0 故障回退、0 页面脚本错误、0 HTTP 资源请求。思考中重开处理耗时约 19.9ms，等待旧请求期限后仍在干净开局状态。

| 指标 | 高级 | 终极 |
| --- | ---: | ---: |
| 搜索返回样本 | 64 | 54 |
| 暖启动 Worker 请求端到端 P95 | 40ms | 178ms |
| 本轮完整深度范围 | 3 至 7 | 3 至 6 |
| 停止原因 | 全部节点上限 | 全部节点上限 |

两局经过不同局面，深度范围不能直接当作同局面强度比较；独立固定局面测试已验证高级与终极会完成不同深度。当前样本没有时间保护先于节点上限的停止；主线程长任务观察记录为空，覆盖仅限本轮两局。参考记录：`output/playwright/high-ai-offline.json`。

首次 Worker 启动分别为约 14.7ms 和 9.1ms；首个请求含启动和搜索分别约 45.2ms、104.6ms。请求时钟从提交给 Worker 前开始，不包括掷骰、走子动画及提交前的中级备用计算。

Worker 创建失败的浏览器故障注入验证通过：合法备用走法继续、兼容模式可见、重开正常。该测试故障不计入正常样本故障率，记录为 `output/playwright/worker-fault.json`。

正式 HTTPS 发布后又分别完成高级、终极各一局，140 和 144 次掷骰，加载后全程断网。91 次正常搜索返回均未触发时间保护或故障，暖启动 Worker 请求 P95 为高级约 29.7ms、终极约 152.6ms。搜索中重开约 13.3ms，等待旧请求期限后没有旧结果回写。记录为 `output/deploy/high-ai-public.json`，公开文件 SHA-256 与本地成品一致。

## 对战证据的边界

使用发布的节点、深度与缓存额度，批测仅移除墙钟保护以保持复现。开发集各比较组预先固定 8 个种子块、每块 4 局，双方轮换阵营与先手。随机裁判与策略流分离，不把未来骰子交给 AI。

这是用于检查策略表现的开发批次，不是正式留出验收。三组结果均保留 manifest、逐局 JSONL 和报告。 统计原论文另有[高校公开副本](https://www.cs.rpi.edu/academics/courses/spring06/random/hoefding.pdf)。统计方法在 `doc/AI评测协议.md` 中预注册为块级 Hoeffding 单侧下界，比原设计拟定的 BCa 更保守；不根据结果临时改统计方法或更换种子求通过。

| 开发比较组 | 高档胜负 | 高档观察胜率 | 错误 / 截断 | 证据 |
| --- | --- | ---: | --- | --- |
| 中级对初级 | 28 胜 4 负 | 87.5% | 0 / 0 | `output/ai-dev-bm/report.json` |
| 高级对中级 | 22 胜 10 负 | 68.75% | 0 / 0 | `output/ai-dev-ma/report.json` |
| 终极对高级 | 16 胜 16 负 | 50% | 0 / 0 | `output/ai-dev-au/report.json` |

全部预定 96 局取得真实终局，没有删除失败或截断局。各组仅 8 个独立种子块，保守下界均未达到门槛，而且它们本来就不是正式留出集。**终极对高级在本批次没有观察到胜率优势，不能据搜索量更大认定其已达到更强档位的验收目标。** 当前发布的是可运行的终极搜索基准，后续优先比较评估参数与有策略的模拟续玩，并保留该基准作对照。

该节点配置下，32 局高级对中级累计约 73.4 秒，终极对高级累计约 578.1 秒。按这批对局的平均成本外推每组 400 块，顺序执行分别约 1.0 和 8.0 小时，另应预留成本波动；这只是后续计划估算，本轮没有执行 4800 局正式留出。估算记录为对应目录的 `estimate.json`。

后续需要根据验证集确定调参方向，再冻结正式留出样本和配置。不能把两个新按钮、更多搜索节点或几局获胜，当成四档难度已得到正式证明。
