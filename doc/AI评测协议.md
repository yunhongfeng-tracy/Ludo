# AI 相邻档位评测协议

日期：2026年09月07日  
协议版本：`adjacent-block-benchmark@1`  
状态：阶段二评测工具与预注册方法，不代表四档强度已经验收。

## 1. 评测范围

工具 `tools/ai-benchmark.cjs` 直接调用产品的规则和 AI 内核，只比较预先指定的三组：中级对初级、高级对中级、终极对高级。正确性、强度和浏览器体验分别验收。开发集与验证集的胜率只能描述该批样本，不能当作正式留出结论。

`init` 冻结配置，不开始对局。`run` 才运行。正式样本量必须在查看留出结果前决定，原设计的每组 400 块、共 4800 局仍是成本估算起点，本协议不自动启动它。

## 2. 快速运行

在项目目录执行，Node 自带模块即可，不安装依赖：

```powershell
# 单组一块，共四局，使用当前产品默认操作额度
node tools/ai-benchmark.cjs init --out output/ai-dev-medium-advanced --mode development --seed dev-search-v1 --pairs medium-advanced --blocks 1 --execution nodes
node tools/ai-benchmark.cjs run --out output/ai-dev-medium-advanced
node tools/ai-benchmark.cjs report --out output/ai-dev-medium-advanced
node tools/ai-benchmark.cjs estimate --out output/ai-dev-medium-advanced --target-blocks 400

# 验证集在新的目录和种子域中运行，可先只执行两局后续跑
node tools/ai-benchmark.cjs init --out output/ai-validation --mode validation --seed validation-budget-v1 --blocks 8 --execution nodes
node tools/ai-benchmark.cjs run --out output/ai-validation --max-games 2
node tools/ai-benchmark.cjs run --out output/ai-validation
```

`--pairs` 可以选择一组或逗号连接的多组。可以用不同目录并行启动不同组；同一目录只允许一个写入进程。`--max-games` 限制本次新增局数，`--max-seconds` 在完整对局之间检查本次时间额度，均不改变 manifest 预定样本量。游戏中途终止进程，下次重跑尚未完整记录的那一局。

`--config` 可接 JSON 文件，例如：

```json
{
  "advanced": { "budgetMs": 150, "maxNodes": 12000, "maxDepth": 64, "maxCacheEntries": 20000 },
  "ultimate": { "budgetMs": 600, "maxNodes": 60000, "maxDepth": 64, "maxCacheEntries": 20000 }
}
```

这些数字只是配置格式示例。未覆盖的值来自初始化时的 `AI.LEVEL_CONFIGS`，实际冻结结果以该次 `manifest.json` 为准。正式评测必须使用发布配置，不能为节省成本调低终极节点数。

两种执行方式：

| execution | 用途 | 约束 |
| --- | --- | --- |
| nodes | 可复现批测 | 保留冻结的节点、深度和缓存额度，只在调用时将时间保护设为 Infinity；manifest 仍保存产品原始毫秒预算 |
| time | 实际时间保护对照 | 同时保留产品毫秒预算和操作额度；设备负载可能改变完成深度与动作，不能承诺逐位复现 |

Node 耗时不是浏览器端到端耗时。需另做浏览器实测，检查产品时间保护是否经常比节点额度更早停止。若两种模式动作或完成深度出现实质差异，节点批测不能直接代表该设备的产品强度。

## 3. 冻结与恢复

`manifest.json` 保存完整种子清单、三组选择、块数、骰数上限、数据集用途、执行方式、产品配置、规则/策略/评估/RNG 版本，以及 engine、AI、工具、本协议的 SHA-256。整个 manifest 再计算一个标识。修改配置、种子或源码后，续跑会拒绝；应另建目录，保留旧批次及其失败记录。

每完成一局即将结果追加到 `games.jsonl` 并执行文件同步。每行包括分配、终局、动作与骰子轨迹摘要、最终状态、诊断、耗时、错误信息和记录哈希。进程正常停止或分批完成后产生 `report.json`。`estimate` 产生 `estimate.json`，根据每组已实测的平均单局计算时间推算目标块数，额外列出两倍规划余量；该余量不是统计置信区间，也不保证后续局耗时完全一致。

末行写入中断时，续跑将原始残留字节另存 `checkpoint-tail.<hash>.txt`，记录 `recovery.jsonl` 后修复末尾。已经完整记录的错误局、截断局也算已执行，不会静默重跑到成功。其它损坏、重复记录或哈希不符直接报错。源码变化后，历史 `report.json` 仍应保留，但不能将旧报告作为当前源码的证据。

`run.lock` 防止同目录并发写入；同机原进程已退出的锁可自动恢复。不要为继续批测手工删除正在运行进程的锁。

## 4. 配对与随机数隔离

每个独立主种子构成一块，共四局。高档分别使用红方和黄方，每种阵营各做一次先手和后手。四局使用同一条裁判骰序列，按实际掷骰的时间顺序消费；不同策略可以改变对局长度，因此不要求双方最终消费相同数量的骰点。

块种子按协议版本、数据集用途、用户种子、比较组和块编号经 SHA-256 派生。裁判骰源和每局每方策略源再用不同用途标签派生，使用版本固定的 Mulberry32 整数生成器。裁判通过拒绝采样把 32 位整数均匀映射到 1 至 6。策略只拿到独立 RNG 函数、公开棋盘和预算，不得到裁判 RNG、裁判种子或未来骰点。开发、验证、留出种子使用不同数据集命名域。

每次 AI 请求独立缓存，和当前产品实现保持一致。统计分析把主种子块视作独立抽样单位，块内四局可相关；不将四局当成四个独立样本。伪随机生成的独立性是该实验模型的假设，本工具不宣称 PRNG 为数学意义的真实随机。

## 5. 预注册统计方法

本协议在正式留出前，**用块级单侧 Hoeffding 下界替代原策略设计中的拟定 BCa bootstrap**。选择原因是实现简单、可直接核对，且在独立有界块抽样假设下提供有限样本的保守界限，不依赖 bootstrap 退化处理。代价是可能需要更多样本或更大的真实优势。依据是 Hoeffding 的有界独立随机变量集中不等式。[原始论文](https://www.tandfonline.com/doi/abs/10.1080/01621459.1963.10500830)

对每块四局，高档胜记 1，负记 0，取平均值 `X_b`，所以 `X_b` 在 `[0, 1]` 内。设完整块数为 `n`，块均值为 `mean`，每组单侧错误率固定为 `alpha = 0.05 / 3`：

```text
radius = sqrt(log(1 / alpha) / (2 * n))
lowerBound = max(0, mean - radius)
```

三组分别使用单侧 98.333...% 下界，通过并集界将本轮三组的总体错误率上界控制为 5%。这个声明以独立块及冻结策略等实验假设为前提，不是 AI 最优性的证明。

每组需同时满足：预定全部局获得真实终局，错误与截断均为零，观察胜率至少 55%，下界严格大于 50%。每组 400 块时，半径约为 7.154 个百分点，因此观察胜率约需超过 57.154% 才能跨过下界门槛。55% 的观察胜率门槛本身不保证显著，不能据此声称原计划局数一定够用。

无完整块时不计算区间。仅完整块用于中间描述，任何未完成局都会阻止正式通过。所有计划局的辅助敏感性结果分别把未完成局计为高档负/胜，不当平局，也不从计划分母删除。

每次发布默认只允许一轮正式留出、一次计划终点查看。`holdout` 初始化要求一次注册三组；未达到预定记录局数时，报告隐藏胜负和区间。原始记录仍需保留供审计，操作者不得提前查看结果后追加样本到通过。未通过要保留失败，不能临时改用 BCa、Wilson 或其它更易通过的方法，也不能不断换种子重试。若未来要调整方法或预注册多轮，应在首次查看正式结果前另定协议与错误率分配。

## 6. 结果边界

错误、非法动作、输入被 AI 修改、引擎异常都记录为正确性失败，不伪装为输棋。默认最多 10000 次掷骰，仍未终局记录为截断。提高该上限需要新的 manifest 和关联说明，保留旧批次记录。

工具报告各档决策 P50/P95/P99/max、节点总数、完成深度分布、停止原因、缓存命中，以及终局和失败数。`strengthAcceptance` 只有正式留出三组全部通过时才为真。工具始终将 `fourLevelReleaseAcceptance` 设为 false，因为无界面对战本身不验证 Worker、浏览器响应、断网和恢复。开发阶段可以交付可用算法候选，但不能把本工具创建成功或少量开发对战说成四档差异已正式证明。
